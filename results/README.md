## 实验 B1 · PubMedQA 文本 CPT → SLAKE SFT (2026-09-16)

配置 `configs/cpt_pubmed_qlora.yaml` (1 万条 pqa_artificial, 1 epoch, lr 5e-5, packing 1024) → `configs/sft_after_cpt.yaml` (从 CPT adapter 继续, 与实验 A 同参数)。
CPT 2 h 39 min (0.42 样本/秒, loss 1.96 → 1.75); SFT 4 h 07 min (loss 1.38 → 0.079, eval 0.160 → 0.142); 评估 1.5 h; 合计 8.4 h。无 NaN。

按题型 B1−A: Position open +2.5, Quantity +3.8, KG open −2.8, Abnormality open −2.4, 其余 ±1 以内。逐题 A→B1: 修正 15 题, 新错 14 题。

结论:
- **纯文本 CPT 对图像 VQA 没有可测增益**: SLAKE 全部指标与 A 的差异在 ±1 内, 逐题互换 15/14, 属随机波动。原因是 CPT 语料 (文献摘要) 与 SLAKE (影像定位/病灶识别) 的知识不重叠, 且 CPT 只动 LLM 部分, 视觉塔冻结。
- **CPT 的收益出现在它自己的领域**: PubMedQA +2.2 (文本推理), 说明 CPT 本身是有效的, 只是没有跨模态迁移。
- **yes 偏置仍在**: no→yes 误判 92 例, maybe→yes 77 例; maybe 只答了 44 个。文本 CPT 没有改善可靠性。
- 由此实验 B2 (图文 CPT, IU X-Ray / CheXpert Plus 的图片+报告) 是必要的, 否则 CPT 阶段对本课题的主指标无贡献。报告中 B1 作为「文本 CPT 不足以提升医学 VQA」的对照证据保留。
- 时间: CPT 的 packing 序列在 T4 上只有 0.42 样本/秒, 1 万条已经 2.6 h; 图文 CPT 数据量要控制在 5k 以内或等学院服务器。

## 实验 B2 · IU X-Ray 图文 CPT → SLAKE SFT (2026-09-16)

配置 `configs/cpt_iu_qlora.yaml` (3483 张正位胸片 → Findings+Impression 报告, caption 式对齐, 1 epoch, lr 5e-5) → `configs/sft_after_cpt_iu.yaml` (与 A 同参数)。
CPT 1 h 19 min (0.73 样本/秒, loss 2.17 → 1.06); SFT 4 h 38 min (loss 0.73 → 0.083, eval 0.168 → 0.151); 评估 1.5 h; 合计 7.7 h。无 NaN。

|---|---|---|---|---|---|
| SLAKE closed acc | 67.31 | 89.18 | 88.70 | 88.70 | −0.48 |
| SLAKE open EM / recall / F1 | 40.62 / 46.73 / 47.53 | 75.35 / 82.17 / 81.56 | 75.81 / 82.72 / 82.07 | 74.57 / 81.61 / 80.88 | −0.8 / −0.6 / −0.7 |
| SLAKE closed X-Ray / CT / MRI | 80.70 / 64.49 / 56.82 | 91.23 / 86.45 / 93.18 | 91.23 / 85.51 / 93.18 | **92.11** / 85.05 / 93.18 | +0.9 / −1.4 / 0 |
| TextVQA acc | 83.89 | 83.89 | 83.78 | 84.00 | +0.11 |
| PubMedQA acc / macro-F1 | 65.80 / 51.03 | 70.60 / 52.38 | 72.80 / 54.19 | 70.80 / 52.96 | +0.2 / +0.6 |
| PubMedQA 预测 yes / no / maybe | 641 / 201 / 158 | 685 / 256 / 59 | 670 / 286 / 44 | 672 / 263 / 65 | 真实 552 / 338 / 110 |

按题型 B2−A: Abnormality open **−9.8** (41.5 → 31.7, n=41, 即少对 4 题), Modality closed −3.0, KG closed −2.6, KG open −1.8; Abnormality closed +1.8, Quantity +1.9, Size open +2.6; 其余 ±1。逐题 A→B2: 修正 11 题, 新错 18 题。X 光片子集: open 76.5 → 74.5, closed 91.2 → 92.1。

CPT 阶段冒烟 (给 3 张验证片写报告): 模型完全学会了放射报告的句式和结构 ("The heart is normal in size. The lungs are clear. No pneumothorax or pleural effusion. Impression: No acute cardiopulmonary abnormality."), 但 3 张里 2 张有异常 (双下肺斑片影 / 右侧胸腔积液) 都被写成正常。

结论:
- **图文 CPT 同样没有给 SLAKE 带来增益**, 整体略降 (open −0.6, 逐题 11 对 18)。X 光片封闭题小涨 0.9 (114 题涨 1 题), 在噪声内。
- **CPT 学到的是语言, 不是视觉**: 报告语体学得很像, 但对异常视而不见, 输出向「正常」模板坍缩。IU X-Ray 训练集里 36% 是正常报告, 且异常报告的句子也大多以否定句 ("no effusion") 开头, caption 式 loss 让模型学会的是高频模板。视觉塔冻结, 视觉特征没有被改动, 所以 CPT 不可能提升「看片」。
- 这也解释了 Abnormality open 的下降: 一个偏向「正常」的先验在识别病灶的题上是负作用。
- 与 B1 合起来的结论: **在 3B 模型、冻结视觉塔、几千条数据的设定下, CPT 阶段对医学 VQA 主指标没有贡献**; 文本 CPT 只在文本任务 (PubMedQA) 上有效。报告主结果是 A, B1/B2 作为「CPT 何时无效」的对照证据。
- 后续如果还要做 CPT, 必须改两处之一: 解冻视觉塔 (或给 ViT 也加 LoRA), 或换成异常均衡的图文对 (CheXpert Plus 按标签抽样)。否则把精力转向 SFT 数据配比 (C)、遗忘基准与可靠性对齐。

- 按模态: CPT 后 MRI 封闭题从 56.8 涨到 69.3 (两种 CPT 一样), X-Ray 反而降 (80.7 → 76.3 / 72.8), 需要逐题看是格式还是内容。

## 修正 · 封闭题评分 (2026-09-19)

SLAKE 的 CLOSED 不等于是非题: 416 道封闭题里有 61 道的标准答案是 Lung / Liver / T2 / Coronal Plane 这类封闭词表。
旧评分 `yes_no(pred) == yes_no(gold)` 把两边都折成 yes/no/other, 于是这 61 道上任何非 yes/no 的回答都折成 "other" 并与标准答案相等, 白算对。
基座不受影响 (它在这些题上硬答 yes/no, 本来就该判错); 学会了答内容词的三个微调 adapter 各被高估 4–5 分。

已改为 `medvlm.metrics.closed_score`: 标准答案是 yes/no 的按是非比, 其余按字面比。
`scripts/rescore_slake.py` 从已存的逐题预测重算, 不需要重跑模型。

| 模型 | 旧 closed | 新 closed | 差 |
|---|---|---|---|
| 基座 | 67.31 | 67.31 | 0 |
| B1 只 CPT | 69.95 | 69.71 | −0.24 |
| B2 只 CPT | 70.43 | 68.27 | −2.16 |
| A 只 SFT | 89.18 | **85.10** | −4.08 |
| B1 CPT→SFT | 88.70 | **83.89** | −4.81 |
| B2 CPT→SFT | 88.70 | **84.13** | −4.57 |

开放题 (EM / recall / F1)、TextVQA、PubMedQA 不受影响。按模态的封闭题同步重算。
逐题变化也随之更新: base→A 修正 328 / 新错 30; A→B1 15 / 17; A→B2 13 / 22。
**结论全部不变**: SFT 仍然是主要增益 (+17.8 而非 +21.9); 三个 SFT 模型依旧彼此在噪声内 (85.10 / 83.89 / 84.13), CPT 无增益的结论更稳。
本文件上方各节的封闭题数字为修正前的值, 保留作为记录; 以 results/*.json 和本节为准。

## 实验 C1 · SLAKE SFT + PubMedQA 三分类回放 (2026-09-19, 服务器 5090)

**动机**: CPT-only 评估 (2026-09-17) 表明 yes 偏置由 SLAKE 短答式 SFT 引入, 不是 CPT 也不是基座。
若诊断正确, 在 SFT 数据里补回三分类样本就该把校准救回来。

**做法**: PubMedQA pqa_labeled 1000 题按标签分层对半切 (`data/pubmedqa_split.json`, seed 42, 入库固定)。
train 半边 500 题按每类 300 条平衡采样成 900 条 (maybe 仅 55 条唯一样本, 重复约 5 次), 与 SLAKE train 4,919 条混合做一次 SFT。
超参与实验 A 完全一致 (r16, lr 1e-4, 3 epoch, 有效 batch 16, seed 42), 唯一变量是这 900 条。
test 半边永不进训练; **PubMedQA 一律只在 test 半边计分** (`scripts/eval_pubmedqa_split.py`)。
训练 1 h 25 min, 1092 步, train loss 0.976 → 0.070, eval loss 0.196 → 0.146 → 0.142 (优于 A 的 0.145)。
技术风险解除: 带图的 SLAKE 与纯文本 PubMedQA 混在同一次 SFT 里, LLaMA-Factory 正常处理。

  no 的召回率 43.8 → 70.4, no 误判成 yes 从 A 的 59 例降到 26 例, 比基座的 42 例还低。
- **SLAKE 没有代价**: closed 84.13、open recall 82.19, 与 A (85.10 / 82.17, Kaggle) 在跨硬件噪声内; 训练中验证损失还略优于 A。
- **代价出现在 TextVQA**: 84.22 → 81.33 (−2.89, 300 题里约 9 题)。这是四轮实验里第一次测出通用能力下降,
  而且是同硬件同探针的干净对比。逐题看: 变差 14 题、变好 6 题, 净 −8 题;
  答案平均长度 1.39 → 1.43 词, 不是答长了。变差的里面两类混杂: 一类是写法差异
  ("one penny" → "1 penny", "BURMAN GEARBOXES" → "Burmans Gearboxes"), 一类是真读错
  ("Vietnam" → "us army", "CellSensor" → "acurite")。幅度小到接近噪声, 但方向为负。
  **归因待定**: A 在 Kaggle 上 TextVQA 没掉, 但那是跨硬件的比较, 要等 A-server 才能判断
  这 −2.9 是混入纯文本造成的, 还是 SFT 本身在这块卡上就会带来的。
- **对齐一章因此可以不必做 DPO**: 问题出在 SFT 数据配比, 补数据即可, 比再加一个训练阶段便宜得多。

**尚缺的对照**: A 是在 Kaggle 上以 4bit QLoRA 训的, C1 是在服务器上不量化 bf16 训的,
二者差了数据配比、量化、硬件三项。校准结论的幅度 (+9.4 macro-F1, maybe 5→19) 远超硬件噪声, 可以成立;
但 "SLAKE 无代价" 是 ±1 分辨率的判断, 要坐实需要在服务器上用 `configs/bf16/sft_slake_qlora.yaml`
重跑一遍 A (记作 A-server), 那才是 C1 的单变量对照。下一轮就跑它。

## 实验 A-server · 实验 A 在服务器上的单变量对照 (2026-09-20)

**为什么跑**: 实验 A 在 Kaggle 上用 4bit QLoRA + fp16 训, C1 在服务器上用 bf16 不量化训,
二者差了「数据配比 / 量化 / 硬件」三项。把 A 用 C1 的条件在同一台机器上重跑一遍,
A-server 与 C1 之间就只剩**那 900 条 PubMedQA** 一个变量。
配置 `configs/bf16/sft_slake_qlora.yaml`, 超参与 C1 完全一致, 924 步 (4,919 ÷ 4 ÷ 4 × 3)。
train_loss 0.0646, eval_loss 0.1446。

### 一、A-server 复现了 A (跨硬件比较是站得住的)

| TextVQA | 83.89 | 83.56 | −0.33 |

| eval_loss | 0.145 | 0.1446 | −0.0004 |

全部在半分以内。**换硬件、换量化方式, 训练动力学和最终表现都重现了**,
所以此前用 Kaggle 数字与服务器数字混排得出的结论不需要推翻。

|---|---|---|---|

### 三、两条待定结论现在定了

**「SLAKE 无代价」—— 基本成立, 但要说得更准**: 封闭题掉 1.21 分 (416 题里约 5 题),
开放题 EM 反涨 0.62 分 (645 题里约 4 题)。全测试集 1,061 题净变化约 1 题。
准确说法是「封闭题有约 5 题的小幅代价, 被开放题的小幅提升抵消, 整体持平」,
而不是先前的「完全无代价」。

**「TextVQA 掉 2.9」—— 可以归因了**, 而且分解得很干净:

| 段落 | TextVQA | 变化 | 归因 |
|---|---|---|---|
| 服务器基座 | 84.22 | — | — |
| → A-server (只做 SLAKE SFT) | 83.56 | **−0.66** | SFT 本身, 噪声级 |
| → C1 (再混入 900 条纯文本) | 81.33 | **−2.23** | **那 900 条** |
| 合计 | | −2.89 | |

**所以通用能力的退化确实是回放数据造成的, 不是 SFT 本身。**
代价换来的是 macro-F1 +9.63、maybe 答对数翻三倍、no→yes 错误减少 37 例。
这是一个清楚的取舍, 可以写进报告: 用 2.2 分的通用 VQA 换回三分类校准。

### 四、顺带发现: A-server 的 yes 偏置比 A 更重

A-server 把 no 答成 yes 的错误有 63 例, 比 A 的 59 例和基座的 42 例都多,
maybe 只答对 6 题。这进一步印证 CPT-only 那一节的结论:
**短答式 SLAKE SFT 会系统性地把模型推向 yes**, 与硬件和量化无关。

## 实验 C2-300 · 回放比例消融的第一个点 (2026-09-22)

C1 用 900 条是拍的。C2 变动回放条数, 把孤点做成曲线。**A-server 就是回放 0 条那个点**,
所以 0 / 300 / 900 三个点已经齐了。三个配置只差 `dataset` 与 `output_dir`, 其余超参完全一致。
训练 981 步 (5,219 样本), 耗时 10 小时 58 分 (约 40 秒一步, 与 A-server 同量级)。

### 结论

**一、校准收益在 300 条就基本饱和。** 0→300 拿到 +9.03 macro-F1, 300→900 只再多 +0.60。
边际收益从每百条 +3.01 掉到每百条 +0.10, **三十倍的衰减**。
这是本实验最有价值的发现: 修复校准所需的回放预算比预想的小得多。

**二、但 300 条矫枉过正, 900 条更均衡。** 300 条把 no→yes 从 63 压到 14 (比基座的 42 还低),
代价是 yes→no 从 18 涨到 32, yes 召回率从 91.7 掉到 69.9, 预测的 yes 只有 228 而真实有 276。
两类危险错误加总 300 条是 46、900 条是 45, **基本打平, 只是分布不同**。
按三类召回率的均衡程度看 (79.7 / 70.4 / 34.5 vs 69.9 / 78.7 / 38.2), 900 条更平。

**三、代价随回放量单调上升。** TextVQA −1.23 → −2.23; SLAKE closed +0.48 → −1.21。
**300 条这一点在主任务上完全没有代价** (封闭题反而 +0.48, 开放题 +0.47),
这比 C1 「小幅代价被小幅提升抵消」的口径更好。

**怎么选取值**: 若优先保住通用能力与主任务, 300 条是更好的工作点 (94% 的校准收益, 一半的代价,
主任务零代价); 若优先三类行为均衡, 900 条更合适。**报告应当把这个取舍讲清楚, 而不是宣布一个"最优值"。**

### 对 1800 那一档的判断

**建议不跑, 或改跑 100 条。** 理由: (a) 收益已在 300 处饱和, 1800 极大概率只是继续加大代价;
(b) maybe 在训练半边只有 55 条唯一样本, 1800 档等于每条重复近 11 次, 真出现回落也分不清是
饱和还是重复过拟合, 结论会含糊; (c) 一轮约 13 小时。
真正信息量更大的缺口在 **0 到 300 之间** (全部收益发生在这一段) 以及 **第二个随机种子**
(300 与 900 之间 yes 召回率差 27 题的非单调变化, 需要确认不是单次运行的抖动)。

## 第二个遗忘探针 · MMBench (2026-09-23)

**为什么加**: TextVQA 只有 300 题、短答式 OCR, 与微调输出格式太像。C2 那条代价曲线的纵轴架在它上面,
形状可信、幅度存疑。MMBench 英文 dev 集固定抽 500 题 (seed 42), 四选一, 覆盖 20 个能力维度,
`eval/eval_mmbench.py`, 已接入 `train/eval_all.sh` 成第四张表。解析失败数四个模型都是 0。

| 模型 | MMBench (500) | TextVQA (300) |
|---|---|---|
| 基座 (服务器) | 88.40 | 84.22 |
| 回放 0 (A-server) | 87.40 | 83.56 |
| 回放 300 (C2) | 87.40 | 82.33 |
| 回放 900 (C1) | 88.00 | 81.33 |

相对回放 0: MMBench **0.00 / +0.60**, TextVQA **−1.23 / −2.23**。MMBench 一分 = 5 题, 回放在它上面没有代价。
逐类别最大的三个变动 (attribute_comparison −5.9、image_style −3.4、object_localization −2.8) 换算都是各 1 题。
SFT 本身 (基座→A-server) 在两个探针上都是小幅: MMBench −1.00 (5 题), TextVQA −0.66 (2 题)。

**结论**: 回放的「通用能力代价」只出现在短答式探针上, 四选一探针完全不动。TextVQA 量到的是**短答输出格式的扰动**
(回放塞入的是 yes/no/maybe 单词答案), 不是视觉能力退化 —— 与此前逐题分析「一半是写法差异」一致。
此前判断「TextVQA 会低估遗忘」**方向反了**: 它相对 MMBench 是高估。报告 5.6 与分析章按此改写。
代价一侧因此比先前写的更小; 收益一侧不变。

### 关于速度: 那个「原因未找到」的 38 秒一步

四轮服务器训练的每步耗时与另一账号任务 `srb` 的状态: C1 (09-19) 4.7 秒, `srb` 不在; A-server (09-20) 38 秒, `srb` 在、负载未记录;
C2-300 (09-21 夜) 40 秒, `srb` 两张卡 100% / 575 W; **s43 (09-23 夜) 2.8 秒, `srb` 在但 0% 待机**。
快慢与那个任务是否满载对应。此前排除了双卡 / 内存 / 磁盘 / 网络 / 线程 / 显存抖动 / 显卡性能七项都没找到原因,
因为原因不在我们这边: GPU 分时共享, 另一进程满载时我们的内核排队等时间片, 表现为「我们的进程闲着、整卡看着也不忙」。
这是四轮的相关性, 不是证明 (A-server 那轮的 `srb` 负载没记录; C2-300 那轮采到的整卡利用率只有 4–15%, 可能是间歇满载)。
**操作上的结论**: 开跑前看 `nvidia-smi` 里别人的进程利用率, 闲着就跑 (一小时出结果), 满载就等。

### 四条结论

**一、饱和成立, 数字收紧: 99 条拿到 63% 的收益, 300 条 92%。** 相对 0 点, 99 条 +5.99, 300 条均值 +8.69, 900 条均值 +9.46。

yes→no 错误 18 → 36 → 31 → 20; no→yes 63 → 12 → 13 → 25.5。任何回放量都先把偏置推过中线, 回放越多拉回得越近真实比例。
300 与 900 之间 yes 召回最小差距 7.6 (72.1 vs 79.7), 大于放宽后的抖动 4.7。**危险翻转总数在所有回放点持平 (48 / 46 / 42 / 45 / 46, 对 0 点的 81), 变的只是拆分。**

**三、99 条不靠重复就把 maybe 这一类修回来了 —— 但只修回「有这一类」, 没修回「什么时候用」。** 99 条那一轮 maybe 每条最多见一次,
maybe 召回率 41.8 反而是六轮里最高的, 所以校准修复不依赖那 55 条的反复重复, 「靠背题」这个内部局限被划了上界。
代价是它把 maybe 答了 120 次 (真实 55), yes 只答 197 (真实 276), 总准确率 64.6 **比 0 点的 68.8 还低**。

## 实验 B3: CheXpert Plus 图文 CPT, 按对齐分数筛选 vs 随机 (3B, 2026-10-02 至 10-04)

**二、按对齐分数筛选看不出作用:** 高分组开放 EM 比随机组高 0.9 (逐题 13 题更好 / 7 题更差, 共 1,061 题), 小于 3B 开放 EM 的种子差 1.4; 其余几项差得更少。
唯一一致的迹象是高分组 CPT loss 略低 (1.176 对 1.200), 但没有传到 SFT 之后。
局限: 每组一个种子; 两组一半数据相同, 真正不同的只有约 2,500 对; 打分模型本身弱 (R@1 1.9%); 下游 SLAKE 对 CPT 本来就几乎没反应。
