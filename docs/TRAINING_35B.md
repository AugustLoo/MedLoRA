# 35B 模型训练说明（预训练还是微调、训练细节）

- 更新：2026-10-12
- 涉及模型：S2-2datasets、S2-6datasets、S2-CheXpertPlus（都在 Intern-S2-Preview 35B 上训练）

---

## 一、一句话回答：是微调，不是预训练

三个模型都是 **LoRA 指令微调（SFT）**：给模型看「问题（可带图片）→ 标准答案」，只在答案部分计算损失，教它按要求回答。
原模型的 350 亿参数**一个都不动**，只训练挂在旁边的一小块「补丁」（LoRA，占全部参数的 0.054%）。

**没有做预训练**（也叫继续预训练，CPT），原因见第五节：在 3B 小模型上试了三次，对主任务都没有帮助。

## 二、基座模型

| 项目 | 内容 |
|---|---|
| 模型 | Intern-S2-Preview（老师提供），在 Qwen3.5 上继续训练而来 |
| 规模 | 35B 总参数，混合专家结构（256 个路由专家，每个词激活 8 个），实际每次约激活 3B |
| 组成 | 语言模型 + 视觉编码器 + 时间序列模块 |
| 思考模式 | 训练和评测时都**关闭**（默认会先写一段推理再回答） |

## 三、训练方法（三个模型完全相同，只换数据）

| 项目 | 设置 |
|---|---|
| 方法 | LoRA：rank 16，alpha 32，dropout 0.05 |
| 挂在哪里 | 语言模型的注意力层（全注意力 q/k/v/o、线性注意力 in_proj_qkv / in_proj_z / out_proj）+ 共享专家（gate/up/down），共 250 个线性层 |
| 可训练参数 | 19,169,280，占 0.054% |
| 不训练的部分 | 256 个路由专家（打包存储，挂不了 LoRA）、路由器、视觉编码器、时间序列模块、词表 |
| 损失 | 只算答案部分，提问和图片不计 |
| 学习率 | 1e-4，余弦衰减，前 5% 预热 |
| 轮数 | 3 轮 |
| 批大小 | 每次 4 条 × 梯度累积 4 = 有效 16 |
| 长度上限 | 1,024 个 token（含图片 token）；超长样本整条跳过（三个模型都是 0 条） |
| 图片 | 等比缩到不超过 262,144 像素（512×512） |
| 随机种子 | 42 |
| 硬件 | 主机 4 张 RTX 5090，模型按层切到 4 张卡上；每步约 6–7 秒 |
| 代码 | 自写 `train/interns2/train_lora.py`（transformers + peft）。LLaMA-Factory 不支持这个模型的结构 |

**为什么只换数据**：三个模型的区别只有训练数据，比较结果时才能说明是数据带来的差别。

## 四、三个模型各用了什么数据

| | S2-2datasets | S2-6datasets | S2-CheXpertPlus |
|---|---|---|---|
| 训练数据 | SLAKE 4,919 + PubMedQA 300 | SLAKE 4,919 + PubMedQA 300 + VQA-RAD 734 + PathVQA 5,000 + MedQA 3,000 + PneumoniaMNIST 2,000 | CheXpert Plus 胸片 → 报告 10,000 对（只用这一种） |
| 合计 | 5,219 条 | 15,953 条 | 10,000 条 |
| 题型 | 医学看图短答 + 是 / 否 / 不确定 | 看图短答、病理图问答、医师考试四选一、儿童胸片判断肺炎 | 看胸片写报告（「检查所见 + 结论」） |
| 训练步数 / 用时 | 978 步 / 1 小时 58 分 | 2,991 步 / 5 小时 40 分 | 1,875 步 / 3 小时 19 分 |
| 最后的损失 | — | 0.032 | 0.757（答案是平均 58 词的报告，本来就降不了那么低） |
| 状态 | 已部署（世龙的服务） | 已评测 | 已评测（2026-10-13） |

**数据的规矩**：
- 每个数据集只用**训练部分**，测试部分只用来考试；
- 训练题里和测试题重复的已经自动剔除；
- VQA-RAD 官方切分里，203 张测试图有 202 张也出现在训练部分，所以把问这些图的 1,059 道训练题全部去掉，只用 734 道；
- CheXpert Plus 的 10,000 对和成人胸片测试用的 3,189 张**不是同一批病人**。这批数据是受控数据，只在服务器上使用。

S2-CheXpertPlus 的提问是三种「写报告」的说法之一（固定随机），答案是医生报告的「检查所见」（有的话）加「结论」。约 71% 的报告没有「检查所见」这一段，报告平均 58 个词。

## 五、为什么没有做预训练

预训练（继续预训练，CPT）= 先让模型读大量领域材料，再做微调。我们在 3B 小模型（Qwen2.5-VL-3B）上试了三次：

| 实验 | 预训练读什么 | 结果 |
|---|---|---|
| B1 | 1 万篇 PubMed 医学论文摘要（纯文字） | 看图问答没提升，纯文字推理略好 |
| B2 | IU X-Ray 3,483 对胸片 + 报告 | 学会了报告的写法，但没学会看出病，主任务没提升 |
| B3 | CheXpert Plus 5,000 对（按队友对齐模型的分数挑，对照组随机挑） | 两组都没提升，按分数挑也看不出比随机好 |

在「视觉编码器冻结、只有几千到一万条数据」的规模下，预训练对主任务没有作用，所以 35B 上直接做微调。
S2-CheXpertPlus 的数据形式（看胸片写报告）和 B2、B3 的预训练很像，但它是**按微调的方式训练**的（同样的 LoRA、只算答案的损失），目的是让模型描述胸片时不再漏报。

## 六、怎么用这些模型

- 训练成果是补丁：`/home/ubuntu/chunqian/MedLoRA/outputs/<模型标签>/adapter_model.safetensors`（77 MB），配置在同目录 `adapter_config.json`。
  - S2-2datasets：`interns2_mix_300`；S2-6datasets：`interns2_6ds`；S2-CheXpertPlus：`interns2_cxp`。
- 开服务（LMDeploy）要先把补丁和原版**合并成完整模型**（约 73 GB，3–5 分钟）：`train/interns2/merge_lora.py`。合并时 MTP 层和 F32 的 lm_head 从原版原样拷回。
- 服务器硬盘大家共用，**同时只放得下一个合并好的新模型**，合并前先协调。

## 七、目前的评测结果（单次训练，种子 42）

| 测试 | 原版 | S2-2datasets | S2-6datasets |
|---|---|---|---|
| SLAKE 医学看图是非题 | 84.4 | 94.5 | 94.7 |
| PubMedQA「不确定」答对 / 55 | 7 | 22 | 23 |
| TextVQA / MMBench（通用能力） | 88.8 / 93.6 | 86.7 / 94.0 | 87.2 / 93.4 |
| PathVQA 病理图是非题 * | 80.1 | 76.8 | **92.7** |
| MedQA 医师考试题 * | 85.0 | 83.6 | **85.3** |
| PneumoniaMNIST 判断肺炎 * | 84.9 | 84.3 | **95.4** |
| 成人胸片：病片描述成「正常」（CheXpert Plus 3,189 张） | 29.2% | 68.5% | **13.8%**（CheXbert 判定 11.2%） |

\* 对 S2-6datasets 来说这几项练过同类题（但没练过测试题），属于「领域内」提升。
每个模型只训练了一次；同一做法训练两次，个别指标可能差很多，S2-6datasets 计划再用种子 43 训练一次确认。
S2-CheXpertPlus：成人胸片描述漏报 14.0%、区分能力 59.6、自相矛盾 7.7%（都是四个模型里最好或接近最好），误报 25.1%；但只练了报告，SLAKE 短答、「不确定」题和外部测试都回到原版水平（详见 results/README.md）。
