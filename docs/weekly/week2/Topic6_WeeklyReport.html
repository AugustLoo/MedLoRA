01 · 起点

上周留下的两句话

上周那份汇报的结尾有一个判断和一个担心。这周的所有实验都是围绕这两句话展开的。

判断：模型不敢说「不确定」这个毛病，不是基座的，也不是增量预训练的，而是 SLAKE 那种「一个词回答」的微调数据带进来的。证据是只做 CPT 不做 SFT 的模型反而校准最好。如果对，把三分类样本补回微调数据里，毛病就该消失——不需要再加一个 DPO 阶段。

担心：通用能力探针 TextVQA 只有 300 题、还是短答式 OCR，和微调输出格式太像，可能测不出遗忘，需要换一个更灵敏的。

「所以对齐要改的是 SFT 的数据配比，而不是再加一个阶段。」
「TextVQA 的短答题和我们的 SFT 输出格式太像，测不出退化。」

02 · 方法

要拿考卷当练习册，先把考卷切一半

三分类样本只有 PubMedQA 有，而它正是可靠性评估表。拿考卷练习，分数不算数。

按标签分层对半切，种子固定 42，切分文件入库到 git，脚本写了保护——一旦存在就拒绝重新生成。一半进训练，一半永远只用来打分。之前四个模型的逐题预测都存着，按切分过滤重算即可，八个模型站在同一把尺子上，没有重复花一次推理。

03 · 主结果

分布是怎么一步步贴回去的

灰色斜纹是真实答案的分布。往下滚，看每加一批回放数据，预测分布怎么变。

PubMedQA 预测的 yes / no / maybe · 考卷半边 500 题
01 / 04

基座：偏 yes，还乱猜 maybe

没微调过的模型答 320 / 97 / 83。yes 多了 44 个，no 少了 72 个。它答了 83 次 maybe，但只对 7 次——不是谨慎，是猜。

02 / 04

只做微调：偏置反而更重

实验 A 在服务器上重跑（回放 0 条）：356 / 112 / 32。maybe 塌掉一半，该答 no 却答 yes 从 42 例涨到 63 例，比没微调时还多。上周的判断在这一步被独立复现：短答式微调系统性地推向 yes。

03 / 04

补 300 条：贴回去了，但过了头

228 / 178 / 94。macro-F1 从 51.5 跳到 60.5，no→yes 错误从 63 压到 14——比基座还低。代价是 yes 只答了 228 个而真实有 276，yes 召回率从 91.7 掉到 69.9。它把偏置推过了中线。

04 / 04

补 900 条：更均衡，收益只多 0.6

269 / 151 / 80，八个模型里最贴近真实的分布。macro-F1 61.1，三类召回率 79.7 / 70.4 / 34.5 比 300 条时平得多。但从 300 到 900，收益只多 +0.6，边际收益掉了三十倍。

回放 0 / 300 / 900 三轮全在服务器上 bf16 不量化跑的，超参一致，可直接相减。
04 · 反驳一个质疑

不是让它多猜「不确定」

最容易被问的一句：你只是把它调得爱说「不确定」而已吧？

基座本来就答了 83 次 maybe，只对 7 次；补 300 条后答 94 次，对 21 次；补 900 条后答 80 次，对 19 次。次数相当，对的次数三倍。三个类别的精确率和召回率是一起变好的。

两类危险错误加起来，300 条是 46、900 条是 45，打平——只是分布不同：300 条把 no→yes 压得极低但 yes→no 涨上来，900 条两头均衡。哪个更好取决于场景，报告里没有硬选一个「最优值」。第二个种子（43）把 300 条这一点重跑了一遍：no→yes 12、yes→no 30、yes 召回 72.1，和种子 42 的 14 / 32 / 69.9 几乎重合——矫枉过正是这个预算的性质，不是一次运行的偶然。

05 · 严谨性

为了只留一个变量，把实验 A 重跑了一遍

实验 A 当初在 Kaggle 的 T4 上 4bit 量化训的，回放实验在服务器 5090 上 bf16 不量化训的，差了三样，不能直接相减。

所以把 A 用同样条件在同一张卡上完整重跑（A-server）。五项指标全部差在半分以内，连最终验证损失都是 0.145 对 0.1446。换硬件、换量化方式，训练轨迹重现了。它同时充当了回放曲线的「0 条」那个点，也部分顶替了第二个随机种子——一次硬件、精度、量化都不同的独立复现。

06 · 代价

掉的到底是什么

收益量清楚了，代价呢？往下滚，两条遗忘曲线会先后出现——第二条推翻了上周的担心。

通用能力 vs 回放条数 · 准确率 %
01 / 04

TextVQA 在掉

回放 0 / 300 / 900 条，TextVQA 83.56 → 82.33 → 81.33。代价随条数单调上升，−1.23 再 −2.23。看起来回放在吃通用能力。

02 / 04

先把微调本身摘出去

基座是 84.22，只做 SLAKE 微调到 83.56，掉 0.66——噪声级别。所以后面掉的那些是回放造成的，不是微调本身。归因干净。

03 / 04

第二个探针：纹丝不动

MMBench 五百题四选一，覆盖 20 个能力维度。回放 0 / 300 / 900：87.40 / 87.40 / 88.00。相对回放 0 是 0.0 / +0.6，一分等于五题，噪声。逐类别最大的变动换算过来各是 1 题。

04 / 04

所以掉的是格式，不是能力

回放塞进去的是 yes / no / maybe 单词答案，短答式 OCR 题对这种输出分布的偏移敏感，四选一的题不受影响。之前逐题看 TextVQA 变差的一半是 one penny → 1 penny 这种写法差异，对上了。上周担心 TextVQA 低估遗忘——方向反了，它高估。

主任务 SLAKE：回放 300 条封闭题反涨 0.48、开放题 EM 涨 0.47，零代价；900 条封闭题掉 1.21、开放题涨 0.62，净约一题。
07 · 取舍

多少回放才够

这是这周最实用的发现：修复校准需要的数据比预想的少得多。

前 300 条换来 +9.03 macro-F1，每百条 3.0 分；再加 600 条只多 +0.60，每百条 0.1 分，边际收益掉三十倍。而代价是单调涨的，只在短答格式上出现。

+9.03300 条

收益几乎一步到位

再到 900 条只多 +0.60。曲线在很早的地方就饱和了，不必跑 1800 条——那一档 maybe 要重复 11 次，真回落也分不清是饱和还是背题。

±0SLAKE · 300 条

主任务零代价

封闭题 +0.48、开放题 +0.47。900 条时封闭题 −1.21 被开放题 +0.62 抵消。小预算连「抵消」都不需要。

300 或 900

没有唯一最优

要通用能力和主任务不掉，选 300；要三类行为均衡，选 900。报告把取舍讲清楚，不替使用者做这个决定。

08 · 结论

第三阶段改写了

课题流水线里「对齐」默认是第三个训练阶段，通常是 DPO。这两周的结果说明，在这个流水线里它可以不要。

可靠性问题不是从预训练继承的，是第二阶段自己制造的——上周的 CPT-only 评估证明前半句，这周的回放实验证明后半句。再加一个阶段等于用新阶段去修上个阶段弄坏的东西。第三阶段因此重新定义为「微调数据配比的设计」，DPO 降为备选。

还有一件事值得说：上周从 CPT-only 评估推出的机制，在被验证之前就预测了这周的结果。这比结果本身更能说明我们理解的是机制，不是在凑数字。而 TextVQA 那个担心被推翻，说明这套评估在自我纠错，不是只挑好看的讲。

10 · 坦白

时间去哪了

两周跑了四轮服务器实验，不是实验慢，是第一次在学院服务器上跑踩了一串坑。记在这里，因为有一条会影响后面的排期。

预处理的假死。进度条长时间停在 0%，其实框架每一千条才刷新一次，它一直在干活。为此误杀过两个健康的运行。后来找到不靠进度条的判断法（看进程累计读取字节数），把批次改小让进度条真正动起来。

线程超额。同一张图用 1 个线程处理 0.021 秒，128 个线程 7.862 秒，差 374 倍，默认值 64。已写进配置。

评估双启动。一条 && 链的父进程还在等训练结束，我又加了一个等待循环，训练一退出两边同时触发评估，两个进程往同一个文件里写，一小时白跑。现在的纪律是开跑前先查有没有别的在等。

没解决的：同一台机器同一个模型，C1 是 4.7 秒一步，之后三轮都是 38–40 秒一步，差八倍。排除了双卡、内存、磁盘、网络、线程、显存抖动、显卡性能（实测 68.5 TFLOPS，正常）七项，调用栈显示卡在反向传播但 GPU 利用率只有 5%。当时原因没找到。种子那一轮给了答案：它只用 45 分钟，2.8 秒一步——跑的时候别人的任务在待机。四轮对照下来，慢的三轮都撞上另一账号的任务满载两张卡，快的两轮那个任务不在或待机。是 GPU 分时共享，不是我们的配置。相关性不是证明，但操作纪律已经定了：开跑前看别人的利用率，闲着就跑。

11 · 下一步

把结论加固，而不是再加点

按优先级

  1. 第二个随机种子。300 条和 900 条之间 yes 召回率差了 27 题，这是单次运行分不清是效应还是抖动的量级。重复 300 条那一点（采样种子和训练种子一起换），已跑完（种子 43）：macro-F1 59.80 对 60.48，yes 召回 72.1 对 69.9，两类危险错误各差 2 例——运行间抖动约 0.7 分。300 到 900 的 +0.95 与抖动同量级，「饱和」成立；而 yes 召回 71.0（两种子均值）对 79.7 的 8.7 分差距是抖动的四倍，「300 条矫枉过正」被加固。剩下没有第二种子的是 0 点和 900 点。
